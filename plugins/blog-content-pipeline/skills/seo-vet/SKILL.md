# SEO & Brand Vetting

Eighth and final step of the content pipeline, and the **fifth (final) approval gate**.

## Steps

1. Run through this checklist against the approved draft and metadata, and fix anything that fails before reporting:
   - **Brand fit**: does the tone actually match `CONSTITUTION.md`'s Voice & Tone, all the way through — not just the intro?
   - **Title quality**: read the frontmatter title, and any separate short-form/thumbnail copy the project derives from it, with zero surrounding context. Does it name a concrete, recognizable situation rather than a bare topic noun? If it uses a resolution-signal word ("how to", "guide", "method", "노하우"), does the post actually deliver a prescription — or was that word bolted onto an explanatory/diagnostic post where it doesn't fit? If short-form copy compresses the title, does it keep the title's real causal relationship (who does what, cause vs. effect) instead of drifting into a weaker or different claim, and does it still read cleanly on its own? If that copy is split across multiple fragments/lines, read them concatenated as one utterance — if a fragment ends in a connective or particle that grammatically demands a specific continuation (contrast, condition, a predicate about its topic), confirm the next fragment actually delivers that instead of an unrelated label swapped in to hit a length limit. If the constitution defines its own title/thumbnail rules (character limits, quantifier placement, phrase-vs-sentence ending, taxonomy pillars, language-specific grammar gotchas), verify those specifically — this generic check doesn't replace them.
   - **Keyword placement**: does the target keyword from `idea-refine` show up naturally in the meta description, at least one H2/H3, and the body?
   - **Frontmatter**: every required field from the constitution present, correctly typed, category value valid, thumbnail filename matches what was actually planned?
   - **Custom components**: every shortcode/component used has correctly closed, correctly cased arguments?
   - **Mapping format**: if the constitution defines a multi-language or structured mapping format, does every instance in the body follow it with no exceptions?
   - **Admonition/FAQ syntax**: matches the constitution exactly, including any documented gotcha (trailing characters, forbidden bold, forbidden shortcodes)?
   - **FAQ standalone quality**: read each FAQ question completely in isolation (hide every other question and the body). Does it fully make sense with no missing context — no dangling "this problem"/"that issue"/"그럼"/"이 문제" pointing at something only defined elsewhere? Does it read like a real, unprompted search query or voice-assistant question, not a lead-in engineered backward from an answer already written? Rewrite any question that fails either test — this is a common, easy-to-miss failure mode even when the syntax is correct.
   - **FAQ incremental value**: for each FAQ question, ask whether it's a genuinely distinct curiosity (a migration/switching detail, an edge case, a boundary condition, a common objection, a practical follow-up) or just the post's main argument re-asked in question form so a pre-written answer has somewhere to sit. If most or all of the FAQ list just mirrors H2 claims from the body, that's a real defect, not a stylistic quibble — replace the weak entries with something a reader would actually wonder next, not restate.
   - **Asset paths**: do image placeholders point to paths consistent with the project's content structure?
   - **Length/depth**: if the constitution defines a minimum length, section count, or depth guidance, does the draft actually meet it? Don't just check a word count in isolation — a post that hits the number but only restates the same point in different words hasn't met the intent either.
   - **Internal links**: if the constitution requires linking to other pieces of content (e.g. a topic cluster, related posts, related docs), does the draft actually contain them, and do they resolve to real, existing content (not a link to something that hasn't been published yet)? If the constitution also asks for backlinks from existing content into this new piece, confirm those got added too.
   - **Closing**: does the last section actually close the piece, or does it just stop after the last supporting point? A ban on cliché wrap-up phrasing ("in conclusion", "to sum up") is not the same as no closing at all — check the constitution's Voice & Tone for how it wants a piece to land (e.g. returning to the opening hook, a concrete next step, a direct answer to the question the piece raised).
2. **Knowledge capture offer**: if this post's research surfaced any fact, nuance, or methodology that's genuinely reusable beyond this one post (and the constitution defines a knowledge base), offer to run the `knowledge-capture` skill now to file it away before publishing. Don't force this — skip if nothing reusable came up, or if the constitution says "Not used" for its knowledge base.
3. Report the vetting results (what was checked, what if anything was fixed) to the user and **wait for explicit final publish approval**. This closes the pipeline — actually committing/publishing the file is a separate, explicit action the user takes or asks for after this approval.
