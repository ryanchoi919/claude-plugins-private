# 데이터 스키마

## 작업 폴더 기본 레이아웃
```
<career-root>/
├── CAREER.md                     # 설정
├── projects/<프로젝트명>.md       # 이력 저장소
├── base/                         # 기본본 3종
│   ├── 경력기술서.md (원본)  <이름>_이력서.html  <이름>_경력기술서.html  <이름>_포트폴리오.html  (+ 같은 이름의 PDF)
├── applications/<회사> <직무>/    # 지원 폴더
│   ├── 공고.md  브리프.md  claims.md  진행 상황.md
│   └── <이름>_<문서종류>_<회사명>.pdf/.html
└── insights.md                   # 회고 누적
```
모든 경로는 `CAREER.md`의 `paths`로 바꿀 수 있다 (예: Obsidian vault라면 `projects: Career/프로젝트`, `applications: Career/지원 이력`, `base: Career`).

## `CAREER.md` (설정)
frontmatter 키:
- `name`, `name_en`(선택), `contact`(`email`·`phone`, `in_documents_only`: 서류에만 쓰는지), `photo`(선택, 경로)
- `paths`: `projects`, `applications`, `base`, `insights`, `output`(제출 PDF를 둘 곳, 예 `~/temp`). 상대 경로는 `CAREER.md` 위치 기준
- `market`: `KR`(기본)
- `career_start`: 첫 경력 시작일(YYYY-MM-DD). 총 경력 연수 검사에 쓴다
- `filename_pattern`: 기본 `{name}_{doc}_{company}` (범용본은 `{name}_{doc}`)
- `money_policy`: 절대 금액 표기 허용 여부 (`allow` 기본, 사용자 확인 후 기록)

본문 섹션:
- `## 문체 선호`: 기본 문체 규칙에 덧붙이거나 바꿀 것
- `## 고정 표기`: 사용자 고유 용어 표기 (예: "<도구명> MCP: 별도 서버를 만든 것이 아님")
- `## 귀속 주의`: 누가 제안·승인했는지 헷갈리기 쉬운 사건 목록
- `## 저장 후 처리`: 파일을 쓴 뒤 사용자 환경에서 해야 할 일 (예: 브랜치 → PR → 머지 → 동기화). 플러그인은 이 절차를 그대로 따른다

## 프로젝트 노트 (이력 저장소)
frontmatter: `회사`, `역할`, `시작일`, `종료일`, `영역`(목록: AX / 데이터 / 전략기획 / 사업운영 / 마케팅 등, 사용자 정의 가능), `임팩트`(핵심 / 보조 / 참고), `tags`, `aliases`, `created`, `modified`, `version`.

본문: `개요`, `배경 / 문제 정의`, `진행 내용`, `성과`, `관련 노트`. 필요하면 콜아웃:
- `> [!note] 사실관계 정정`: 근거가 약하거나 틀렸던 내용과 정정 이유
- `> [!note] 범위 재정의`: 프로젝트의 결론·범위를 사용자가 다시 정한 경우
- `> [!note] 귀속`: 제안·승인·실행 주체
- `> [!note] 신뢰도 메모`: 본인 진술 기반이라 외부 문서에서 보수적으로 써야 하는 항목
- `[확인 필요: ...]`: 아직 근거가 없는 항목

새 사실을 확인받으면 콜아웃 제목 끝에 `(YYYY-MM-DD 본인 확인)`을 붙인다.

## 지원 폴더
- `공고.md`: frontmatter `회사`, `공고`, `지원일`, `상태`, `version`, `tags`, `aliases`, `created`, `modified`. 본문에 원문(직무·자격·우대·제출 서류 요건), 포지션 개요, 자체 판단 표
- `상태` 값(고정 8개): `준비 중` / `서류 제출` / `서류 전형` / `서류 탈락` / `면접` / `최종 합격` / `불합격` / `지원 취소`
- `브리프.md`: brief 스킬의 7개 절, frontmatter `승인: true|false`
- `claims.md`: 아래 형식
- `진행 상황.md`: 작업 기록, `## 검수 결과 (YYYY-MM-DD)`, `# 결과 (YYYY-MM-DD)` 섹션

## 주장 원장 `claims.md`
한 줄 = 주장 하나. 6열 표:

| ID | 주장(서류에 쓸 표기) | 값 | 출처 노트 | 귀속 | 금지·주의 표현 |
|---|---|---|---|---|---|
| C01 | 3개월간 품절 발생 품목 수 40개 → 22개 (45% 감소) | 40개, 22개, 45%, 2024.06.03–09.02 | projects/재고 예측 대시보드 구축.md | 제안: 팀장, 설계·구현: 본인 | "최대 50% 감소" → "45% 감소" |

- ID는 `C` + 두 자리 숫자
- 금지·주의 열: `"금지 문구" → "대체 표기"`. 여러 개는 `;`로 구분. 화살표 왼쪽 큰따옴표 안 문구만 금지 표현으로 검사된다 (`scripts/lint_docs.py`)
- 서류 작성 단계는 원장의 표기만 쓴다. 원장에 없는 숫자가 필요하면 원장에 먼저 추가하고 출처를 확인한다

## `insights.md`
공고 유형별 표:

| 지원 건 | 공고 유형 | 결과 | 전면 프로젝트 | 강조점 | 갭 | 메모 |
|---|---|---|---|---|---|---|

하단 `## 패턴 요약`. 표본이 적을 때는 "가설"로 표시하고 단정하지 않는다.
