# 커리어 갱신

스키마: `${CLAUDE_PLUGIN_ROOT}/references/schemas.md`. 사실 규칙: `${CLAUDE_PLUGIN_ROOT}/references/attribution-and-facts.md`

## 0. 선행 확인
- 작업 폴더의 `CAREER.md`를 `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/config.py <CAREER.md>`로 읽는다. 없으면 setup 스킬로 보내고 멈춘다
- `<base>/`에 기본본 3종이 없으면 갱신이 아니라 생성이므로 setup의 기본본 단계로 보낸다

## 1. 바꿀 것 모으기
- 사용자 요청을 분류한다: 새 프로젝트 / 성과·수치 / 사실 정정 / 분류 변경(`영역`·`임팩트`) / 범위 재정의 / 문체·고정 표기
- `<applications>/*/진행 상황.md`에서 제목이 `기본본 갱신 필요`로 시작하는 섹션을 모은다. 회사판 검수(review)에서 기본본에서 이어진 문제로 판정된 항목이다. 이미 처리된 항목(`(처리 YYYY-MM-DD)` 표시)은 건너뛴다
- 모은 항목을 문서별(이력서·경력기술서·포트폴리오)로 묶어 한 번에 보여주고, 근거가 노트에 없는 수정만 사용자에게 묻는다

## 2. 이력 저장소 먼저
- 프로젝트 노트를 먼저 고친다. 기존 성과 문장은 지우지 말고 맥락에 맞지 않는 것만 고치며, 정정은 콜아웃 `> [!note] ... (YYYY-MM-DD 본인 확인)`으로 남긴다
- 사람·조직 단위 사실(직함 변천, 팀 규모와 그 시점, 상시 업무)은 프로젝트 노트가 아니라 경력 개요 노트나 `CAREER.md`의 `## 경력 타임라인`에 둔다. 목표 직무·조건이 바뀌면 `## 경력 방향`을 고치고 search 조건을 다시 제안할지 묻는다. 새 프로젝트를 받을 때는 `${CLAUDE_PLUGIN_ROOT}/references/career-interview.md` 5층 질문을 쓴다. 서류 표기 규칙(예: 기술 수준을 어떤 범위로 쓸지)은 `CAREER.md`의 `## 고정 표기`에 둔다
- 새 프로젝트는 스키마의 frontmatter(`영역`·`임팩트` 포함)로 만들고, 분류가 애매하면 사용자에게 묻는다

## 3. 기본본 3종 고치기
- 기본본은 템플릿에서 다시 만들지 않는다. 기존 기본본을 백업한 뒤, 바뀐 프로젝트와 1단계 항목에 해당하는 부분만 고친다 (write-resume·write-career-description·write-portfolio의 기본본 모드 규칙과 문체 규칙을 따른다)
- 포트폴리오는 build_variant 계약(표지·목차·케이스 마크업과 케이스 앞 HTML 주석)을 깨지 않는다. KPI 카드는 결과 지표만 둔다
- 문장이 길어지면 레이아웃이 밀린다. 고친 뒤 반드시 다시 렌더하고 확인한다
  - 이력서·경력기술서: `pdf_check.py`로 쪽수와 `sign_only_last_page`. 경력기술서는 `--max-pages 3`
  - 포트폴리오: 바꾼 슬라이드를 `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/chrome.py shot <html> <png> 1123 631`로 찍어 도식과 카드가 겹치지 않는지 수정 전 기본본 스크린샷과 비교한다
- review 스킬 기본본 모드로 검수한다. 필수 0건이 될 때까지 고친다
- 처리한 항목은 각 `진행 상황.md`의 해당 항목 끝에 `(처리 YYYY-MM-DD)`를 붙인다

## 4. 진행 중 회사판
- `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/status.py scan <applications>`로 상태가 `준비 중`·`서류 제출`·`서류 전형`·`면접`인 지원 건을 찾는다
- 바뀐 프로젝트·문구를 쓰는 회사판 목록을 상태와 함께 보여주고 파생 갱신 여부를 묻는다
  - `준비 중`: 갱신 권장 (아직 제출 전)
  - `서류 제출`·`서류 전형`: 이미 제출한 서류는 다시 내지 않는다. 면접 대비용으로 바뀐 사실만 `진행 상황.md`에 메모할지 묻는다
  - `면접`: 서류는 그대로 두고, 바뀐 사실·수치를 면접 방어 목록에 반영할지 묻는다
- 갱신하기로 한 건만 각 건에서 write-* → review

## 5. 저장
- `CAREER.md`의 `## 저장 후 처리`를 그대로 수행한다. 없으면 파일만 둔다
- 사용자에게 알릴 것: 고친 노트·기본본 목록, 처리한 `기본본 갱신 필요` 항목 수, 남은 권장 항목, 파생 갱신하지 않은 진행 중 건
